# Go: Map, Arrays/Slices, Channels — Interview Questions & Answers

---

## Map

### Что такое мапа?
`map[K]V` — это хеш-таблица в Go, где `K` — тип ключа, `V` — тип значения. Мапа обеспечивает быстрый доступ к значению по ключу.

### Как устроена мапа под капотом?
Под капотом мапа реализована как хеш-таблица с открытой адресацией и бакетами. Каждый бакет хранит до 8 пар ключ/значение. Используется 2 уровня хеширования: основной и эвакуационный (при росте таблицы).

### Какие ключи могут быть у мапы?
Ключи должны быть **сравнимыми** (`comparable`) — поддерживают оператор `==` и `!=`.  
Разрешены типы: числа, строки, указатели, каналы, интерфейсы (если содержимое сравнимо), массивы фиксированной длины (если их элементы сравнимы).  
**Нельзя использовать**: слайсы, мапы, функции.

### Map и Concurrency

#### Что произойдет при конкуррентной записи в мапу?
Паника: `fatal error: concurrent map writes`.  
Обычные мапы **не потокобезопасны**, использовать без синхронизации запрещено.

#### Как работает эвакуация данных?
Эвакуация происходит при **расширении хеш-таблицы**. Go переносит данные из старых бакетов в новые, может быть частично ленивой, чтобы избежать пауз.

#### Потокобезопасная ли мапа?
Нет. Только с использованием внешней синхронизации (`sync.Mutex`, `sync.RWMutex`) или со спец. типом `sync.Map`.

#### Map vs Sync.Map

|                  | map[K]V       | sync.Map         |
|------------------|---------------|------------------|
| Безопасность     | нет           | да               |
| Производительность| высокая       | ниже на чтение   |
| Сценарий         | общее использование | редкие записи, частые чтения |
| API              | стандартный   | `Store`, `Load`, `Delete`, `Range` |

---

### Какая сложность работы с мапой?

- **В среднем**: `O(1)` на вставку, удаление, доступ по ключу.
- **В худшем случае** (при коллизиях или эвакуации): `O(n)`.

---

### Можно ли взять адрес элемента мапы и почему?

Нет. Нельзя взять адрес значения мапы напрямую: `&m[k]` — **ошибка компиляции**.  
Причина: при изменении карты значение может переместиться, и адрес станет невалидным.

## Arrays & Slices

### Что такое слайс?
Слайс — это **описание** части массива. Он содержит:
- указатель на массив,
- длину (`len`),
- емкость (`cap`).

### Чем массив отличается от слайса?
|                      | Массив `[N]T`         | Слайс `[]T`                |
|----------------------|-----------------------|----------------------------|
| Размер               | Фиксированный         | Динамический               |
| Передача в функции   | Копируется полностью  | Копия структуры (указатель остаётся) |
| Память               | Внутри структуры      | Указатель на внешний массив |

**Плюс массива**: лучше подходит для low-level задач, отсутствие аллокаций.

---

### Как работает append?
`append(slice, elems...)`:
- Если в слайсе хватает `cap`, элементы добавляются туда же.
- Если нет — выделяется новый массив, данные копируются.

Возвращается **новый слайс**.

---

### Какие методы оптимизации работы со слайсами ты бы применил в работе?

- Предварительное выделение памяти: `make([]T, 0, N)`.
- Использование `copy` для быстрой передачи данных.
- Избегание утечек через "зависание" ссылок на большой массив (отрезать `slice = append([]T(nil), slice...)`).
- Использование `[:0]` для повторного использования буфера без аллокаций.

---

### Какая есть функция для создания слайса с длиной отличной от нуля?
`make([]T, length, capacity)`  
Например: `make([]int, 5, 10)` — слайс длиной 5, вместимостью 10.

---

### С какой скоростью идет поиск в массиве и почему?
Линейный поиск: `O(n)`, т.к. элементы не упорядочены и приходится проверять каждый.

## Channels

### Что такое каналы?
Каналы (`chan`) — средство синхронной или асинхронной коммуникации между горутинами.  
Позволяют передавать значения и синхронизировать выполнение.

---

### Как устроен канал и как он работает под капотом?
Канал — структура с кольцевым буфером (если буферизован), мьютексами, очередями отправителей и получателей.  
Передача данных синхронизируется через блокировки: если нет получателя — отправитель блокируется, и наоборот (если канал небуферизованный).

---

### Какие есть типы каналов в Golang?

- **Небуферизованные** (`make(chan int)`) — синхронные: отправка блокируется до чтения.
- **Буферизованные** (`make(chan int, N)`) — асинхронные: блокируются при заполнении.

Также каналы бывают:
- **Однонаправленные**: `chan<- T`, `<-chan T`.

---

### Что если писать/читать в закрытый канал?

- **Чтение** из закрытого канала: получаем zero-value и `ok == false`.
- **Запись** в закрытый канал: **паника** (`panic: send on closed channel`).

---

### Какие операции есть с каналами?

- `ch <- val` — отправка
- `val := <-ch` — получение
- `close(ch)` — закрытие
- `<-ch, ok := <-ch` — чтение с флагом
- `select` — мультиплексирование

---

### Как сделать канал буферизованным?
`make(chan T, capacity)`  
Пример: `make(chan int, 10)`.

---

### Какие параметры могут иметь каналы?

- Тип передаваемых данных.
- Буфер (0 — небуферизованный, N — буферизованный).
- Направление (двунаправленный, только для чтения/записи).

---

### Для чего используется `select` при работе с каналами?

Для одновременного ожидания операций на нескольких каналах.  
Позволяет:
- читать из первого готового канала,
- таймауты (`time.After`),
- default-блок при отсутствии операций.

---

### Что если закрыть закрытый канал?
Будет **паника**: `panic: close of closed channel`.

---

### Что произойдет с читателями/писателями если закрыть канал?

- **Читатели**: будут получать значения до опустошения, затем `zero-value` + `ok == false`.
- **Писатели**: при попытке записи — **паника**.
