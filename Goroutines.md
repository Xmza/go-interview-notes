## Что такое горутина?
Горутина — это лёгкий поток выполнения, запускаемый с помощью go перед вызовом функции. Планируется и управляется Go-рантаймом, а не ОС.

<pre>- Запускается: `go someFunc()` 
- Работает асинхронно и конкурентно.
- Может быть тысячи одновременно — дешёвы в создании и переключении. </pre>

## Чем горутина отличается от треда?
Горутина легче, дешевле и управляется рантаймом Go, тогда как треды создаются и управляются ОС и тяжелее по ресурсам.

<pre>- Горутина: ~2KB стека на старте, может расти. 
- Тред: фиксированный стек, десятки/сотни KB. 
- Горутина переключается Go-планировщиком, тред — ОС. </pre>

## В чем преимущества горутин над тредами?
Они потребляют меньше памяти, быстрее создаются и масштабируются, позволяя эффективно обрабатывать множество задач параллельно.

<pre>- Позволяют легко писать конкурентный код. 
- Изолированы, не блокируют друг друга (если правильно синхронизированы). 
- Используются в сетевых приложениях, серверах, пайплайнах. </pre>

## Что есть в Golang для многопоточности?
Горутины, каналы, пакет sync, атомики и планировщик Go — инструменты для управления параллелизмом и синхронизацией.

<pre>- `go`: запуск горутин 
- `chan`: связь между горутинами 
- `sync.Mutex`, `sync.WaitGroup`, `sync.Once` 
- `sync/atomic`: неблокирующие операции </pre>

## Какие есть способы связи между горутинами, какие плюсы и минусы?
1. Каналы (chan)

Позволяют безопасно передавать данные между горутинами. Работают по принципу: один пишет — другой читает.
<pre>+ Просто писать и читать. 
+ Безопасно: не нужно синхронизировать вручную. 
– Немного медленнее, чем работа с памятью напрямую. 
– Может блокировать: горутина "висит", пока вторая не прочитает/запишет. </pre>
2. Общая память + sync.Mutex

Горутины работают с одними и теми же переменными, но доступ к ним блокируется через мьютексы (замки), чтобы избежать гонки данных.
<pre>+ Быстро. 
– Нужно вручную следить за синхронизацией. 
– Ошибки легко допустить: забыть Lock/Unlock → deadlock или race. </pre>
3. sync.Map

Специальная потокобезопасная мапа. Позволяет читать и писать одновременно без блокировок, подходит для кэширования и чтения.
<pre>+ Безопасный доступ из нескольких горутин. 
+ Нет явного мьютекса. 
– Подходит не для всех сценариев (оптимизирован для частого чтения). </pre>


`В Go есть несколько способов коммуникации между горутинами. Основной и наиболее идиоматичный - это каналы, которые реализуют принцип "share memory by communicating". Они отлично подходят для передачи данных и событий. Для защиты общих структур данных лучше использовать sync.Mutex. Атомарные операции хороши для простых счетчиков. WaitGroup помогает дождаться завершения группы горутин. Важно выбирать подход исходя из конкретной задачи, учитывая компромиссы между производительностью и безопасностью.`
