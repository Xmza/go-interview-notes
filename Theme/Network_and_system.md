## Как работает context.Context и зачем нужен
context.Context нужен для управления временем жизни операций: через него удобно задавать отмену, таймауты и дедлайны.  
Когда родительский контекст отменяется, все дочерние функции получают сигнал через ctx.Done().  
Это стандартный способ в Go аккуратно управлять горутинами и асинхронной работой»

- Контекст создаётся через context.Background() или context.TODO().
  - На его основе можно сделать “дочерние” контексты:
  - context.WithCancel — можно вручную отменить.
  - context.WithTimeout — сам отменится через время.
  - context.WithDeadline — отменится к заданному моменту.

- Когда контекст отменяется, его канал ctx.Done() закрывается, и все функции, которые его слушают, могут завершить работу.
- Также можно класть в контекст значения через context.WithValue, но это не для бизнес-логики, а только для сквозных данных (трассировка, логирование, id запроса).

---

## Чем отличается context.WithCancel vs WithDeadline vs WithTimeout

* `WithCancel` — создаёт контекст, который можно отменить вручную вызовом `cancel()`;
* `WithDeadline` — автоматически завершится к указанному времени;
* `WithTimeout` — то же самое, но через фиксированный интервал.

Все возвращают `ctx, cancel := ...` и требуют `defer cancel()`.

---

## Что будет если не вызывать cancel

Будет **утечка ресурсов**: контекст держит таймеры, каналы и горутины. Без `cancel()` они висят до выполнения GC.

## Как устроен net/http-сервер под капотом
net/http сервер открывает TCP-листенер, на каждый входящий коннект создаётся горутина.  
Запросы парсятся в http.Request и обрабатываются через ServeHTTP; keep-alive и заголовки управляются пакетом автоматически

`TCP-листенер — точка входа для соединений по TCP;`  
`keep-alive — механизм повторного использования одного TCP-соединения для нескольких запросов;`      
`ServeHTTP — метод обработчика, вызываемый для каждого HTTP-запроса;`  
`http.Request — структура, содержащая данные HTTP-запроса.`   

<pre>Под капотом: listener.Accept() -> горутина -> ServeHTTP(handler)</pre>
