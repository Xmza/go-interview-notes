## Как устроен reflect и зачем нужен

`reflect` позволяет работать с типами и значениями во время выполнения. Используется для:

* сериализации (например `encoding/json`);
* ORM;
* написания универсальных библиотек.

Под капотом: `reflect.Value` хранит тип и указатель на данные. Операции медленнее, чем прямой вызов.

## Что такое generics в Go какие ограничения

Generics (обобщённое программирование) — это возможность писать функции и структуры, которые работают с разными типами данных, сохраняя безопасность типов на этапе компиляции. В Go дженерики появились в версии 1.18 (2022 год).
Ограничения:

- Тип-параметр не может быть абсолютно любым типом, если явно не указано any.
- Можно ограничивать с помощью interfaces, например:
  - T int | float64 — только эти типы
  - T interface{ Comparable } — любые сравнимые типы
  - Если ты хочешь делать с generics какие-то операции (сравнение, арифметику и т.п.), компилятор должен быть уверен, что этот тип это поддерживает. Для этого используют constraints.

Пример:

```go
func Sum[T int | float64](a, b T) T {
    return a + b
}
```

## Чем отличаются interface{} vs any

* `interface{}` — старый способ обозначить любой тип;
* `any` — алиас для `interface{}` с Go 1.18, используется для читаемости.

## Как работает unsafe.Pointer и когда его использовать

unsafe.Pointer в Go — это универсальный указатель без типа, позволяющий обойти систему типов и работать напрямую с памятью.
Через него можно:

- приводить один тип указателя к другому,
- преобразовывать указатель в uintptr и обратно (например, для арифметики адресов),
- обращаться к внутреннему представлению структур.

`Использовать его стоит только когда невозможно решить задачу обычными средствами Go: системные вызовы, работа с сырой памятью, высокопроизводительные библиотеки.
Он опасен, потому что компилятор не контролирует корректность таких преобразований, и можно получить segfault или некорректные данные.
`

## Что такое atomic.Value и когда использовать вместо мьютекса

`atomic.Value` хранит одно значение и позволяет атомарно читать/записывать его без мьютексов. Подходит, когда много читателей и мало обновлений, например, для конфигурации или кэша. Для сложной синхронизации всё равно нужен мьютекс.

---

## Как устроен sync.Once

`sync.Once` внутри хранит флаг и мьютекс, он гарантирует, что функция выполнится ровно один раз.

* Проверяет флаг `done` атомарно;
* Если `false` — блокирует мьютекс и выполняет функцию;
* Устанавливает `done=true`.

## Зачем нужен build-tags

Build tags в Go нужны, чтобы управлять тем, какие файлы войдут в сборку в зависимости от условий: ОС, архитектуры, версии Go, кастомных тегов.

Зачем нужны:
- Писать платформо-зависимый код (например, отдельные реализации для Linux и Windows).
- Собирать разные варианты программы (например, с debug-логами и без).
- Исключать тестовые или экспериментальные части кода.

```go
//go:build linux

package main

func platform() string {
    return "Linux"
}
```

<pre>Обычно применяют для кроссплатформенного кода или генерации разных бинарей.</pre>
