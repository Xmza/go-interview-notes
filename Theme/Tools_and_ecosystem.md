## Что делает go mod tidy go mod vendor go mod graph

* `go mod tidy` — убирает неиспользуемые зависимости и добавляет недостающие.
* `go mod vendor` — скачивает все библиотеки (например, github.com/...), которые использует ваш проект, и кладёт их в папку ./vendor рядом с вашим кодом. Чтобы не зависеть от интернета при сборке
* `go mod graph` — показывает дерево зависимостей вашего проекта в виде списка связей чтобы увидеть, какие библиотеки тянет ваш проект (и их версии). Найти конфликты версий или ненужные зависимости. :
ваш_проект → библиотека_1 → библиотека_2 → ...

## Как устроен go build какие этапы компиляции

Этапы компиляции:
go build компилирует Go-код в бинарный файл, проходя через анализ зависимостей, компиляцию пакетов и линковку.
Этапы компиляции

- Анализ зависимостей
  - Go ищет все импорты (import) и проверяет go.mod.
  - Скачивает недостающие модули (если go get не был выполнен ранее).
  - Строит граф зависимостей, чтобы понять порядок компиляции.

- Компиляция пакетов
  - Каждый .go-файл преобразуется в промежуточный объектный файл (.a).
  - Происходит оптимизация: инлайнинг функций, удаление мёртвого кода.
  - Генерируется SSA-форма (Static Single Assignment) для низкоуровневой оптимизации.

- Линковка
  - Объектные файлы объединяются в исполняемый бинарник.
  - Добавляется рантайм Go (горутины, сборщик мусора, планировщик).
  - Если есть cgo, подключаются C-библиотеки.

- Финальный бинарник
  - Получаем один файл (например, main или main.exe).
  - Он автономный — не требует установки Go на машине, где запускается.

## Что делает go generate

go generate — это команда, которая автоматически запускает кодогенерацию в Go-проекте. Она ищет специальные комментарии //go:generate в исходных файлах и выполняет указанные в них команды (например, генерацию кода для сериализации, API-клиентов и т.д.).


<pre>go build компилирует код, а go generate создает его перед компиляцией.</pre>

## Как работает go fmt и go vet

* `go fmt` — автоформатирование кода (отступы, скобки, пробелы).
* `go vet` — статический анализатор, ищет потенциальные баги (неиспользованные переменные, printf с неправильными аргументами и т.д.).

## Что такое pprof и как с ним работать

`pprof` — «pprof помогает найти “узкие места” по CPU и памяти, чтобы оптимизировать производительность».

Как работает:

В коде подключается пакет:
```go
import _ "net/http/pprof"
```

Запускается HTTP-сервер:
```go
go func() {
    log.Fatal(http.ListenAndServe("localhost:6060", nil))
}()
```

С помощью go tool pprof можно собирать профили:

```go
go tool pprof http://localhost:6060/debug/pprof/profile
```

В pprof есть команды:

top — показывает функции, потребляющие больше всего CPU.

list <func> — показывает исходный код функции с указанием времени исполнения.

web — визуализация графа вызовов (требуется Graphviz).
