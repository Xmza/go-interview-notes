## Чем отличается параллелизм от конкурентности

* **Конкурентность** — способность программы управлять множеством задач, которые могут выполняться *попеременно* (но не обязательно одновременно).
* **Параллелизм** — физическое выполнение нескольких задач одновременно (многоядерный CPU).

<pre>
Go даёт конкурентность (через горутины и каналы), а параллелизм зависит от GOMAXPROCS и числа ядер.
</pre>

---

## Сколько по умолчанию горутин может выполняться параллельно (GOMAXPROCS)

По умолчанию `GOMAXPROCS = runtime.NumCPU()`.
Это значит, что одновременно может выполняться столько горутин, сколько доступно ядер у процессора.

Можно изменить:

```go
runtime.GOMAXPROCS(2)
```

## Как работает work stealing в планировщике

Go использует M\:N планировщик:

* M — системные потоки (OS threads),
* N — горутины,
* P — процессоры (виртуальные, абстракция для работы планировщика).

**Work stealing**: если один P простаивает (нет горутин в очереди), он может украсть горутину у другого P.
Это балансирует нагрузку и повышает производительность.

---

## Что будет если main завершится а горутины продолжают работать

Когда функция `main()` завершается, завершается и программа.
Все оставшиеся горутины принудительно убиваются.

<pre>
В Go нет фоновых "демон-потоков" — main управляет всей жизнью программы.
</pre>

## Что такое deadlock и как его поймать

**Deadlock** — ситуация, когда горутины навсегда ждут друг друга или ресурс, который никогда не освободится.
В Go рантайм сам детектит deadlock при работе с каналами:

```
fatal error: all goroutines are asleep - deadlock!
```

---

## Что такое livelock чем отличается от deadlock

* **Deadlock** — работа остановлена, горутины спят.
* **Livelock** — горутины активны, но не продвигаются (например, бесконечно перекладывают работу друг на друга).

<pre>
Разница: при livelock программа "крутится на месте", при deadlock — стоит.
</pre>

---

## Чем отличается blocking vs non-blocking канал

* **Blocking**: операция записи/чтения останавливает горутину, пока другая сторона не выполнит обратную операцию.
* **Non-blocking**: используется `select { case ... default: }` — если канал недоступен, выполняется `default`, и горутина не блокируется.

Пример non-blocking send:

```go
select {
case ch <- v:
    // отправили
default:
    // канал занят, пропускаем
}
```
