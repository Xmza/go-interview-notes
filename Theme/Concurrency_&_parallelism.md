## Чем отличается параллелизм от конкурентности

* Конкурентность (concurrency) — это свойство программы быть разделённой на несколько независимых задач, которые могут выполняться как будто одновременно. Они не обязаны реально выполняться в один момент — достаточно того, что выполнение может чередоваться.

* Параллелизм (parallelism) — это одновременное физическое выполнение нескольких задач на разных процессорных ядрах.
---
🔹 Конкурентность (одно ядро, задачи чередуются)
```perl
Время →
Task A:  ----////----////----////----
Task B:      ----////----////----
```

> Они чередуются, реально выполняется только одна задача в момент времени, но выглядит как будто вместе.

🔹 Параллелизм (два ядра, задачи реально идут одновременно)
```perl
Время →
CPU1:   ----///////////----
CPU2:   ----///////////----
```

> Обе задачи выполняются в одно и то же время — реально быстрее.

<pre>
Go даёт конкурентность (через горутины и каналы), а параллелизм зависит от GOMAXPROCS и числа ядер.
</pre>

## Сколько по умолчанию горутин может выполняться параллельно (GOMAXPROCS)

GOMAXPROCS задаёт количество потоков ОС, которые могут выполняться параллельно.
По умолчанию это равно числу логических CPU(`GOMAXPROCS = runtime.NumCPU()`.).

Это значит, что одновременно может выполняться столько горутин, сколько доступно ядер у процессора.

Можно изменить:

```go
runtime.GOMAXPROCS(2)
```

## Как работает work stealing в планировщике

Work stealing в планировщике Go

  - У каждого P (processor, логический планировщик в Go) есть своя локальная очередь goroutine.
  - Когда у M (OS thread, привязанный к P) заканчиваются задачи в своей очереди, он не простаивает, а идёт и крадёт часть задач из очереди другого P.
  - Крадёт обычно половину очереди, чтобы балансировать нагрузку.

Таким образом достигается:

  - Равномерное распределение goroutine по всем ядрам.
  - Минимизация простоя — если один поток освободился, он сразу подхватывает работу.
  - Локальность — пока есть задачи у себя, выполняются они, а не бегаем по чужим очередям.

<pre>В Go планировщик использует work stealing: у каждого P есть своя очередь goroutine, и если она пуста, 
поток крадёт половину задач из очереди другого P. Это позволяет эффективно балансировать нагрузку между ядрами.</pre>

## Что будет если main завершится а горутины продолжают работать

Когда функция `main()` завершается, завершается и программа.
Все оставшиеся горутины принудительно убиваются.

<pre>
В Go нет фоновых "демон-потоков" — main управляет всей жизнью программы.
</pre>

## Что такое deadlock и как его поймать

Deadlock — это ситуация, когда одна или несколько goroutine (или потоков) ждут ресурсы друг друга бесконечно, и никто не может продолжить работу.

1. Как поймать deadlock
  - Go runtime делает это автоматически
  - Если все goroutine заблокированы и никто не может продолжить, Go выдаст panic: all goroutines are asleep - deadlock!
2. Отладка вручную
  - Использовать go tool trace или pprof для анализа блокировок.
  - Логировать операции блокировки (каналы, mutex), чтобы видеть зависшие goroutine.
3. Синхронизационные паттерны
  - Проверять порядок захвата mutex’ов, избегать циклических зависимостей.
  - Использовать select с default для каналов, чтобы избежать блокировки.

## Что такое livelock чем отличается от deadlock

1.  **Deadlock** — работа остановлена, горутины спят.
2.  **Livelock** — это когда Goroutine активно выполняются, но из-за постоянной реакции на состояние друг друга не могут продвинуться к цели.
То есть работа вроде идёт, но эффективного результата нет. Пример: две goroutine постоянно отпускают и заново пытаются захватить mutex, чтобы дать друг другу возможность, но так и не достигают цели.
<pre>
Разница: при livelock программа "крутится на месте", при deadlock — стоит.
</pre>

## Чем отличается blocking vs non-blocking канал

* **Blocking**: Blocking канал — goroutine ждёт, пока операция завершится.
* **Non-blocking**: используется `select { case ... default: }` — Goroutine проверяет: можно отправить/принять? Если нет — идём дальше, не висим.

Пример non-blocking send:

```go
select {
case ch <- v:
    // отправили
default:
    // канал занят, пропускаем
}
```
