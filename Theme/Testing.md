## Как устроен пакет testing

`testing` — это встроенный пакет для написания unit-тестов, бенчмарков и примеров.
При `go test` Go сам генерирует main, где запускается testing.Main.

Основные структуры:

*testing.T — для юнит-тестов (TestXxx), управление ошибками, под-тесты, параллельный запуск.  
*testing.B — для бенчмарков (BenchmarkXxx), регулирует число повторов N.  
*testing.M — для общей инициализации через TestMain.  

Тесты идут в алфавитном порядке, по умолчанию синхронно, но можно t.Parallel().

Есть ключи -v, -run, -bench, -cover.

Каждый тест выполняется изолированно, с отчётами об ошибках и временем выполнения.

## Что такое t.Helper

`t.Helper()` помечает функцию как «вспомогательную» для тестов.

Сам хелпер нужен → чтобы убрать копипасту и сделать тесты короче.

А t.Helper() внутри хелпера → нужен, чтобы отчёты об ошибках указывали на сам тест, а не на вспомогательные функции.

Пример:

```go
func checkErr(t *testing.T, err error) {
    t.Helper() // теперь ошибка укажет на место вызова checkErr, а не сюда
    if err != nil {
        t.Fatal(err)
    }
}
```

## Как писать table-driven-tests

Table-driven tests — это когда ты описываешь все кейсы в виде таблицы (слайс структур), а потом прогоняешь их в цикле. Это канонический стиль тестов в Go.

```go
func TestAdd(t *testing.T) {
    tests := []struct {
        name string
        a, b int
        want int
    }{
        {"1+1", 1, 1, 2},
        {"2+3", 2, 3, 5},
        {"-1+1", -1, 1, 0},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := Add(tt.a, tt.b)
            if got != tt.want {
                t.Errorf("got %d, want %d", got, tt.want)
            }
        })
    }
}
```

Плюсы: читаемость, расширяемость, возможность параллелизации (`t.Parallel()`).

## Как замерять производительность go-test--bench

Чтобы замерять производительность, пишется функции BenchmarkXxx(b *testing.B).  
Go сам подбирает количество итераций b.N, и код надо запускать внутри цикла for i := 0; i < b.N; i++ { ... }.  
Запускаю через go test -bench=..  
Для параллельных нагрузок есть b.RunParallel, а если нужно — можно снимать профили CPU/памяти (-cpuprofile, -memprofile) и анализировать их с pprof.

## Что такое race-detector go-test--race

Race detector (go test -race) — это встроенный инструмент Go, который при выполнении тестов отслеживает гонки данных. Он запускает код с дополнительной проверкой всех операций с памятью и сообщает, если несколько горутин одновременно обращаются к одной переменной без синхронизации.
