## Что такое мапа?
Map в Go — это хеш-таблица, которая хранит пары ключ-значение.  
Используется для быстрого поиска, вставки и удаления элементов по ключу.

<pre>- Ключи уникальны, значения могут повторяться. 
- Позволяет быстро искать, добавлять и удалять элементы. 
- Создаётся через make, например: `make(map[string]int)`. 
- Ключи могут быть только сравнимыми типами (например, строки, числа, указатели).
- Значения можно читать и записывать по ключу: `m[key] = value`, `val := m[key]`. </pre>

## Как устроена мапа под капотом?
Мапа в Go — это хеш-таблица с массивом бакетов (buckets). Каждый бакет хранит до 8 пар ключ-значение. При добавлении ключа считается хеш, выбирается бакет по хешу, и (hash % количество бакетов) кладём пару в бакет, если есть место , если же места нет, то это называется "Переполнение бакета" - запускается перераспределение (rehash) - создаётся новый массив бакетов больше по размеру - элементы перемещаются постепенно (evacuation) - Evacuation — постепенный перенос элементов для балансировки мапы и уменьшения пауз при увеличении.

## Какие ключи могут быть у мапы?
Ключи должны быть типов, которые реализуют интерфейс comparable — то есть могут использоваться оператором ==. Это:
- базовые типы: int, string, bool, float64 и т.д.
- указатели: *T
- интерфейсы: interface{} (если лежащие внутри значения сравнимы)
- структуры: struct{} (если все поля сравнимы)
- массивы: [N]T (если все элементы сравнимы)

<pre> - Нельзя использовать срезы: `[]T`, мапы: `map[K]V` и функции: `func()`, так как они несравнимы </pre>

## Map и concurrency

### Что произойдет при конкуррентной записи в мапу?
Map в Go не потокобезопасна. При одновременной записи из нескольких горутин без синхронизации произойдет гонка данных что приведет к runtime с сообщением "concurrent map writes".
<pre> Для безопасного доступа нужна синхронизация: mutex, sync.Map или другие механизмы. </pre>

### Как работает эвакуация данных?
Когда мапа заполняется и достигает порога загрузки, начинается эвакуация, создаётся новый массив бакетов в 2 раза больше старого. 
- Каждый бакет из старого массива разбивается на новые бакеты по хешу.
- Эвакуация не делается за один раз — она поэтапная (incremental), чтобы не блокировать выполнение программы.
- При каждом обращении к мапе Go перемещает часть данных из старого массива в новый (ленивая эвакуация).
- Пока эвакуация не завершена, мапа умеет читать и писать из обоих массивов, направляя операции в правильный бакет.
- После полного перемещения старый массив удаляется, ссылки переходят на новый. 

### Потокобезопасная ли мапа?
Нет, стандартная map не потокобезопасна. Для безопасного доступа из нескольких горутин нужно использовать мьютексы или sync.Map.

### Map vs Sync.Map
`map` — обычная хеш-таблица. Не потокобезопасна. Требует внешней синхронизации (sync.Mutex, sync.RWMutex) при доступе из нескольких горутин.
`sync.Map` — потокобезопасная мапа из пакета sync. Подходит для сценариев с высокой конкуренцией.

<pre>- map: 
  + Быстрее в однопоточном коде. 
  + Гибкость и контроль.
  - При конкурентной записи может паниковать. 
  - Нужно использовать мьютексы вручную.  
- sync.Map: 
  + Безопасен при доступе из нескольких горутин без мьютексов. 
  + Оптимизирован для сценариев "много чтений, мало записей".
  + Методы: Store, Load, LoadOrStore, Delete, Range. 
  - Медленнее обычной map при большом числе записей. </pre>

## Какая сложность работы с мапой?
Средняя сложность операций — O(1) для поиска, вставки и удаления. В худшем случае — O(n), если много коллизий.

## Можно ли взять адрес элемента мапы и почему?
Нет, нельзя. Элементы map могут пересоздаваться и перемещаться во время перераспределения памяти, поэтому адрес элемента не стабилен и нельзя на него ссылаться.
