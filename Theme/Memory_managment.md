## Как устроен GC в Go
Go использует параллельный, трёхцветный, mark-and-sweep GC.

Трёхцветная маркировка: объекты делятся на белые (неизвестные), серые (обнаруженные, но ещё не пройдены), чёрные (живые).

GC проходит в несколько фаз:

Mark — помечает достижимые объекты (корни: стеки, глобальные переменные).

Sweep — очищает недостижимые (белые).

Stop-the-world (STW): мир приостанавливается для некоторых шагов (например, старт/финал сборки), но большая часть работы выполняется параллельно.

Generational idea: хотя GC не классический поколенческий, новые объекты проверяются чаще, старые реже затрагиваются.

С каждой версией Go GC оптимизируется, снижая паузы STW (сейчас ~<1 мс).

<pre> Главная цель GC Go — минимальные паузы для веб/сервисов, даже ценой немного большего потребления памяти. </pre>

## Что такое escape analysis
Escape analysis — это анализ, который выполняет компилятор Go, чтобы определить, где именно хранить переменную: на стеке или в куче.  
По умолчанию Go старается хранить переменные на стеке (это быстрее и не нагружает GC).  
Если переменная «убегает» за пределы области видимости функции (например, возвращается по указателю, попадает в замыкание или в интерфейс), то она размещается в куче.  

Чтобы посмотреть результат анализа, используется флаг:  
```bash
go build -gcflags="-m" main.go
```

Компилятор напишет, какие переменные перемещены в кучу.

Зачем это важно:  
Переменные на стеке освобождаются автоматически при выходе из функции → очень быстро.  
Переменные в куче требуют работы сборщика мусора → это дороже.  
Поэтому понимание escape analysis помогает писать более эффективный код.

`В отличие от Java, где JIT может решить в рантайме, где хранить объект, в Go решение принимается во время компиляции. Если компилятор сомневается, он выбирает кучу, чтобы гарантировать безопасность.`

## Как устроен heap vs stack в Go

`Стек (Stack)`  

Что такое: область памяти, которая хранит локальные переменные функций, параметры и адреса возврата.

- Особенности:

  - очень быстрый доступ (CPU-friendly),
  - растёт и сжимается автоматически по мере вызова функций,
  - память на стеке освобождается, когда функция завершает работу.
- Горутина и стек: каждый G имеет свой стек; по умолчанию маленький (~2 KB), может динамически расширяться.

`Куча (Heap)`

Что это: область памяти для объектов, которые должны жить дольше функции или слишком большие, чтобы помещаться в стек.

- Хранит:

  - структуры, срезы, карты, каналы, объекты, на которые есть указатели, которые «убегают» (escape).

- Особенности:
  - медленнее стека, потому что управление сложнее,
  - выделение и освобождение памяти управляет GC,
  - Go использует локальный кеш (mcache) и глобальную кучу (mheap) для ускорения аллокаций.

<pre> Stack дешевле, heap дороже → Go старается всё держать в стеке через escape analysis. </pre>


## Что такое zero value и зачем Go так сделан

Zero value в Go — это значение по умолчанию, которое получает любая переменная, даже если её явно не инициализировать.  
Для чисел это ноль, для строк пустая строка, для bool — false, для ссылочных типов — nil.

Сделано это для того, чтобы убрать целый класс ошибок, которые есть в C и C++, где переменные могут хранить мусор, если их не инициализировать.  
В Go переменная всегда находится в определённом состоянии, и ты можешь сразу использовать её без лишней инициализации.

## Что такое arena allocator

Arena allocator — это экспериментальный механизм (Go 1.22+), позволяющий выделять память группами.

Arena allocator — это способ управления памятью, когда заранее выделяется большой блок, и потом память раздаётся из него простым сдвигом указателя. Это очень быстро и без фрагментации, но освобождение идёт не по отдельным объектам, а сразу всей ареной.

Пример:

<pre>a := arena.New()
defer a.Free()

s := arena.MakeSlice[byte](a, 0, 1024)</pre>

<pre> Идеально для временных структур, JSON-парсинга, batch-операций. </pre>
