## Как устроен GC в Go
Go использует параллельный, трёхцветный, mark-and-sweep GC.

Трёхцветная маркировка: объекты делятся на белые (неизвестные), серые (обнаруженные, но ещё не пройдены), чёрные (живые).

GC проходит в несколько фаз:

Mark — помечает достижимые объекты (корни: стеки, глобальные переменные).

Sweep — очищает недостижимые (белые).

Stop-the-world (STW): мир приостанавливается для некоторых шагов (например, старт/финал сборки), но большая часть работы выполняется параллельно.

Generational idea: хотя GC не классический поколенческий, новые объекты проверяются чаще, старые реже затрагиваются.

С каждой версией Go GC оптимизируется, снижая паузы STW (сейчас ~<1 мс).

<pre> Главная цель GC Go — минимальные паузы для веб/сервисов, даже ценой немного большего потребления памяти. </pre>

## Что такое escape analysis

Escape analysis — это процесс компилятора, который решает: переменная живёт в стеке или в куче.

Если значение может безопасно храниться в стеке (локальная переменная, не утекает наружу) → остаётся на стеке.

Если значение «утекает» (возвращается из функции, хранится в замыкании, передаётся в горутину) → перемещается в heap.

Проверить можно командой:

go build -gcflags="-m"


Она покажет, какие переменные «escapes to heap».

<pre> Heap дороже стека (нужна работа GC), поэтому оптимизация = минимизировать escape. </pre>

## Как устроен heap vs stack в Go

`Stack:`
- область памяти для локальных переменных,
- быстрый доступ (LIFO),
- управляется без GC.

`Heap:`
- для долгоживущих объектов,
- память выдаёт runtime,
- освобождается GC.

<pre> Stack дешевле, heap дороже → Go старается всё держать в стеке через escape analysis. </pre>


## Что такое zero value и зачем Go так сделан

Zero value — это значение по умолчанию для любого типа:

- int → 0
- string → ""
- bool → false
- pointer, slice, map, func, chan → nil

Зачем:
- Упрощает код, не нужно инициализировать явно.
- Исключает проблему "мусора" как в C.
- Делает код безопаснее и короче.

<pre> "Zero value is useful" — философия Go. Код работает предсказуемо даже без явной инициализации. </pre>

## Что такое arena allocator

Arena allocator — это экспериментальный механизм (Go 1.22+), позволяющий выделять память группами.

Выделяешь арену → создаёшь объекты в ней → одним вызовом освобождаешь всё сразу.

Ускоряет работу (нет GC для этих объектов).

Ограничение: объекты из арены нельзя хранить после её освобождения.

Пример:

<pre>a := arena.New()
defer a.Free()

s := arena.MakeSlice[byte](a, 0, 1024)</pre>

<pre> Идеально для временных структур, JSON-парсинга, batch-операций. </pre>
