## recover происходит только в той горутине где произошла паника
recover — это встроенная функция в Go, которая позволяет перехватить panic и восстановить выполнение программы.

recover срабатывает только в той же горутине, где была вызвана panic, и только внутри defer.

<pre>- Если паника случилась в другой горутине, `recover` в текущей её не поймает. 
- Чтобы ловить панику в каждой горутине, нужно оборачивать тело горутины в анонимную функцию с `defer func() { if r := recover(); r != nil { ... } }()` 
- Это важно при запуске воркеров, API-хендлеров, потоков обработки и т.п. </pre>

## Чем отличается работа с ошибками в Golang от других языков?
В Go ошибки — это значения, не исключения. Ошибки возвращаются явно и обрабатываются вручную.

<pre>- Нет `try/catch` как в Java, Python. 
- Используется `error` — это интерфейс с методом `Error() string`.
- Ошибки возвращаются как второй аргумент: `res, err := doSomething()` </pre>

## Какая парадигма в Golang с точки зрения обработки исключений и ошибок?
В Go отсутствует традиционная парадигма обработки исключений через `try-catch`, как это реализовано в других языках. Вместо этого используется явная обработка ошибок через возвращаемые значения.
Go придерживается концепции упрошенной обработки ошибок.
- ошибки не являются исключениями, они являются обычными значениями.
- обработка ошибок осуществляется сразу после вызова функций, что улучшает читабельность и предсказуемость кода.
- это способствует написанию кода в стиле "маленьких функций", каждая из которых обрабатывает свои ошибки.

## Какие есть функции для оборачивания и сравнения ошибок?
- `errors.New()`: Создает новую ошибку с заданным сообщением.
- `fmt.Errorf()`: Используется для форматирования ошибки и добавления контекста. Это эквивалент оборачивания ошибки в более сложное сообщение
- `errors.Is()`: Проверяет, является ли ошибка `err` конкретной ошибкой `target`, что полезно для работы с обернутыми ошибками
- `errors.As()`: Позволяет проверить, является ли ошибка определенного типа и извлечь ее.

## Для чего используется паника?
panic используется в крайних случаях — когда программа не может продолжать работу (например, баг, нарушен инвариант).

<pre>- Паника вызывает немедленный крах программы, если не обработана с помощью функции `recover` 
- Обычно `panic` не для бизнес-логики. Идеален для "что-то пошло совсем не так" — нарушение структуры, коррумпированные данные и т.д. 
- Используется в assert-подобных ситуациях, например, в тестах или при нарушении неявного контракта. </pre>
